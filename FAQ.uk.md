## Вибір шляху

### Чотири варіанти використання

**1 · 3.x у графічному вікні (Autosound TCC).** Найбільш автоматизований шлях. Інсталятор встановлює Claude Code, Python, ядро методу, графічний інтерфейс та автоматичного ШІ-критика.
* **Вимоги:** macOS/Windows, платний Claude Pro/Max, бета-версія REW з увімкненим API, ~700 МБ місця.
* **Переваги:** Ви бачите дерево системи, графіки замірів, покроковий план та чат в одному вікні. Зручний реєстр версій налаштувань та швидке скасування будь-яких дій.
* **Недоліки:** Графічний застосунок перебуває у стані бета-тесту.

**2 · 3.x у терміналі.** Те саме ядро та автоматизація, але робота суто через текст у консолі. Встановлюється через інсталятор із прапорцем `--terminal`.
* **Вимоги:** Ті самі підписки, але без потреби у графічній оболонці.
* **Переваги:** Менше навантаження на систему, швидкий текстовий інтерфейс. Проєкт сумісний із графічним застосунком (можна відкрити ту саму папку пізніше).

**3 · Лінійка 2.x (Перевірений чемпіон).** Плагін для Claude Code, зафіксований на стабільній версії `v2.8.3` (гілка `2.x`). Саме на ній було виграно чотири чемпіонати EMMA та AYA у 2026 році.
* **Вимоги:** Платний Claude Pro, бета REW, робота в терміналі.
* **Переваги:** Повністю відпрацьований, стабільний алгоритм. Отримує виправлення помилок, але нові функції сюди не додаються.
* **Недоліки:** Немає автоматичного обліку станів (все ведеться у текстових Markdown-файлах), немає методу «Спочатку за столом» та нових розрахункових утиліт.

**4 · Веб-чат (Без встановлення програм).** Робота вручну через гілку [manual_step-by-step](https://github.com/ayukhno/autosound-tuning-skill/tree/manual_step-by-step).
* **Вимоги:** Безкоштовний Google AI Studio або будь-який веб-чат з ШІ.
* **Переваги:** Абсолютно безкоштовно, не потребує встановлення софту на комп'ютер. Чудово підходить для першого ознайомлення.
* **Недоліки:** Весь процес виконується вручну (копіювання промптів, експорт файлів з REW), немає інтеграції через API, немає автоматичної перевірки розрахунків.

### Який варіант обрати?

- **Максимум можливостей та візуалізація:** Оберіть **Варіант 1** (TCC).
- **Звична робота в консолі:** Оберіть **Варіант 2** (3.x Terminal).
- **Потрібен гарантований результат змагань:** Оберіть **Варіант 3** (2.8.3).
- **Безкоштовний тест без зобов'язань:** Оберіть **Варіант 4** (веб-чат).

*Примітка:* Ви не обмежені у виборі — проєкти 3.x легко відкриваються як у консолі, так і у графічній програмі TCC, а перехід з 2.x на 3.x повністю автоматизований.

### Як визначити вже встановлену версію?
- **За командою встановлення:** Якщо ви запускали `/plugin install autosound-tuning` — у вас 2.x. Якщо запускали скрипт `curl … | bash` / `irm … | iex` — у вас 3.x.
- **За файлами проєкту:** Папка 2.x містить `dsp-state-current.md`. Папка 3.x містить `project.json` та `process-state.json`.
- **У програмі:** У TCC перейдіть у *Diagnostics → Installation*.

### Як залишитися на стабільній лінійці 2.x
Автоматичне оновлення плагінів не переведе вас на 3.x примусово. Щоб жорстко зафіксувати версію та отримувати лише точкові виправлення помилок, клонуйте репозиторій локально:
```bash
git clone -b 2.x https://github.com/ayukhno/autosound-tuning-skill.git ~/autosound-2x
```
Потім у Claude Code виконайте:
```bash
/plugin marketplace add ~/autosound-2x
/plugin install autosound-tuning
```
Оновлюйте плагін за бажанням через команду `git -C ~/autosound-2x pull`.

### Перехід з 2.x на 3.x
На одному комп'ютері може бути активний лише один такий плагін. Перед встановленням 3.x видаліть стару версію в Claude Code:
```
/plugin uninstall autosound-tuning
/plugin marketplace remove autosound-tuning-skill
```
Після встановлення 3.x імпортуйте поточний стан авто (кросовери, затримки, гейни, еквалайзер) у новий формат за допомогою скрипту:
```sh
python3 ~/.claude/skills/.autosound-tuning-src/skills/autosound-tuning/rew_tool/state/migrate.py <старий-проєкт> --into <новий-проєкт>
```

### Головні зміни в 3.x
- **Проєкт як структура даних:** Стан системи зберігається у `project.json` та `process-state.json`. ШІ зчитує точні факти, а не намагається згадати їх із контексту чату.
- **Метод «Спочатку за столом»:** Лише один візит до авто для зняття акустичного відгуку (зйомка). Вся подальша розробка кросоверів, затримок та еквалайзера робиться за комп'ютером на основі точного прогнозування суми фаз.
- **Математична верифікація:** Спеціальні скрипти розраховують фазове узгодження за критерієм мінімальних втрат суми, обмежують добротність (Q) еквалайзера залежно від розкиду точок замірів та виявляють часовий зсув мікрофона.
- **Автоматичні відмови:** Якщо дані суперечливі або мікрофон дав велику похибку часу — система зупинить роботу та відхилить заміри замість видачі неточного результату.

## Філософія та архітектура: навіщо тут ШІ?

### Місія та концепція
**Інтелектуальний екзоскелет** для налаштування звуку: людина (Арбітр) слухає, оцінює сцену і вирішує; ШІ бере на себе розрахунки — фази, затримки, керування REW через API.

### Чому це спеціалізований скіл, а не звичайний чат?
- **Усунення втрати пам'яті (memory drift):** звичайний чат після кількох годин починає забувати початкові числа й суперечити сам собі. Тут стан лежить у `project.json` на диску, і ШІ перечитує його при кожному запиті — пам'ять не «згадується», а читається.
- **База знань автозвуку:** Скіл містить готові правила безпеки для твітерів, алгоритми фазового зведення, цільові криві та логіку аналізу кабіни, про які загальні моделі ШІ не знають.
- **Інтеграція з REW API:** Сирі дані замірів (тисячі точок) обробляються локальними Python-скриптами за мілісекунди. ШІ отримує лише лаконічне резюме, що повністю виключає помилки ручного введення та значно економить ваші кошти.

### Карта налаштування: фази −1…5 та підхід «Спочатку за столом»

| Фаза | Де відбувається | Що виконується | Результат |
| :--- | :--- | :--- | :--- |
| **−1 Підготовка** | за столом | Введення параметрів авто, динаміків, можливостей DSP та вибір цільової кривої. | Створення `project.json` та конфігурації. |
| **0 Зйомка** | в автомобілі | Замір кожного динаміка окремо з **захисними** фільтрами (HPF); свіпи та RTA заміри в русі. | Один перевірений та якісний пакет замірів (раунд). |
| **1 Основа** | за столом | Розрахунок кросоверів, гейнів, затримок та полярності на основі прогнозування суми фаз. | Базове налаштування системи в реєстрі версій. |
| **2 Еквалайзер** | за столом | EQ приходить **пакетами** в такому порядку: резонанси драйвера → форма ліво/право → тон до цілі. За замовчуванням лише зрізи, до 6 смуг на канал, кожен пакет — одне «так/ні» й одна версія реєстру. | Готові файли експорту еквалайзера для вашого DSP. |
| **3 Вердикт** | в автомобілі | Введення чисел у DSP. Контроль введеного перевіряє, чи справді авто звучить так, як передбачив розрахунок. | Повністю зафіксоване технічне налаштування. |
| **4 Слухання** | в автомобілі | Тестові треки (диски EMMA / AYA, CarMus, Chesky) і шпаргалка «на що слухати». Якщо щось «ріже вухо» чи «гуде» — скіл перетворює це на короткий ранжований список підозрюваних і править по одній смузі з A/B, максимум три кола. | Живі слухові вердикти, прив'язані до версій. |
| **5 Варіації** | за столом/в авто | Налаштування додаткових пресетів (під різні жанри, центральний канал тощо). | Додаткові пресети без зміни технічної основи. |

*Примітка:* Якщо реальні заміри в авто на Фазі 3 розходяться з математичним прогнозом, система автоматично відкотить крок назад і перейде до класичного покрокового ітеративного алгоритму.

### Що метод категорично відмовляється робити?
- **Записувати дані напряму у ваш DSP** — введення параметрів завжди залишається за вами.
- **Рахувати затримки за одним заміром** — потрібно мінімум 4 незалежні оцінки часу.
- **Підсилювати звук у зонах фазових провалів (нулів)** — такий провал робить не динамік, а інтерференція, тож заповнити його підсиленням **неможливо в принципі**: у точці слухача нічого не зміниться, а динамік і підсилювач тим часом працюють на межі. Яму, яку підняти можна, від нуля відрізняє тест надлишкової фази (Excess phase у REW) — підіймається лише перша.
- **Працювати з неякісними замірами** — виявлений температурний зсув мікрофона або відсутність захисних фільтрів призведуть до відхилення раунду.

### Які моделі ШІ офіційно підтримуються?
* **Основна модель (Генератор):** Claude Opus (рівень зусиль `xhigh`).
* **ШІ-Критик (Рецензент):** Gemini Pro (High).

*Станом на серпень 2026.* Назви й рівні моделей змінюються щомісяця — якщо ви читаєте це помітно пізніше, звіряйте, що зараз є еквівалентом.

> [!IMPORTANT]
> **Не знижуйте рівень зусиль Claude нижче `xhigh`.** Слабші моделі не повідомляють про помилку — вони просто тихо погоджуються з вами та вигадують технічно неможливі параметри налаштувань.

### Варіанти підписок та бюджет на ШІ

- **Варіант 1 (Рекомендований): Claude Pro ($20/міс) + безкоштовний Gemini як Критик.** 
  Найкращий баланс ціни та надійності. Використовуйте безкоштовний API-ключ Gemini з Google AI Studio. Підписку можна скасувати одразу після налаштування авто.
- **Варіант 2 (Бюджетний): Тільки Gemini ($10 депозиту на Google Cloud).**
  Дуже дешево, але вимагає від вас самостійної перевірки кожної цифри та регулярного очищення контексту через `/clear`, оскільки другого ШІ для перевірки немає.
- **Варіант 3 (Професійний): Claude Pro ($20) + платний API Gemini Cloud.**
  Повна відсутність будь-яких лімітів на швидкість запитів. Ідеально для регулярного налаштування багатьох автомобілів.

### Чому реальні витрати токенів нижчі, ніж здається?
Сирі заміри в чат не потрапляють: тисячі точок стискають локальні скрипти, історія проєкту лежить на диску, а з доктрини завантажується лише поточна фаза (принцип ковзного вікна). Платите за **рішення**, а не за переказ даних.

## Перше встановлення (macOS та Windows)

### Автоматичне встановлення
Вам знадобиться ноутбук, вимірювальний мікрофон, DSP-процесор та платна підписка **Claude Pro або Max**.

<details>
<summary><b>Інструкція для macOS</b></summary>

1. Відкрийте програму **Термінал** (клавіші `Cmd + Space` → введіть `Terminal` → `Enter`).
2. Вставте команду та натисніть Enter:

## Графічний застосунок Autosound TCC

### Що це таке і чи потрібен він мені?
[TCC](https://github.com/ayukhno/autosound-tcc) показує метод у графічному вікні (macOS і Windows): структура системи, графіки REW, план і чат із ШІ на одному екрані. Не обовʼязкова: усе те саме робиться в терміналі, бо дані лежать у звичайних файлах. Застосунок молодший за сам метод — це бета.

### Робота на два вікна (Термінал + Графіка)
Програма та термінал використовують одні й ті самі файли проєкту. Ви можете вільно перемикатися між ними: будь-які кроки чи версії налаштувань, створені в консолі, миттєво відображаються в графічному інтерфейсі, і навпаки.

### Моделі ШІ в застосунку
Застосунок використовує ваш платний тариф Claude (через офіційний Anthropic SDK) та безкоштовний Google-акаунт через локальний клієнт `agy` для роботи ШІ-критика. Альтернативні моделі стають доступними лише за умови активації системи `omp` (тарифікуються окремо).

### Оновлення та повідомлення про помилки
Програма оновлюється самостійно разом із математичним ядром. Перевірити поточні версії можна у вкладці *Diagnostics → Installation*. Помилки інтерфейсу надсилайте через кнопку *Report a problem* на GitHub програми TCC, а помилки логіки налаштування — у репозиторій самого скіла.

## Автономний ШІ-Критик Gemini/Antigravity

Другий ШІ ловить те, чого перший не бачить у власній роботі, і працює у фоні через локальний скрипт — нічого перекладати руками не треба. Це необовʼязково, але саме звідси більшість користі.

### Встановлення для macOS та Windows (Рекомендовано)
Офіційний клієнт **Antigravity CLI (`agy`)** від Google не потребує API-ключів: вхід через браузер.

1. **Встановлення:** інсталятор уже зробив це за вас. Вручну:
   - *macOS:* `curl -fsSL https://antigravity.google/cli/install.sh | bash`
   - *Windows:* `irm https://antigravity.google/cli/install.ps1 | iex`
2. **Вхід:** Запустіть команду `agy` у новому терміналі, увійдіть у браузері під Google-акаунтом, який має доступ до Antigravity, після чого поверніться в консоль і введіть `/quit`.
3. **Тест:** Перевірте роботу командою `agy -p "Hello, world!"`.

### Резервний варіант: Прямий API-ключ Gemini
На операційній системі Linux або при вичерпанні лімітів Antigravity ви можете використовувати безкоштовні ключі Gemini API напряму:
1. Отримайте безкоштовний API-ключ на сайті **[aistudio.google.com/apikey](https://aistudio.google.com/apikey)**.
2. Створіть файл `.critic-env` у папці **вашого проєкту** — усередині `rew_analitic/` або в теці, з якої ви запускаєте роботу, — і запишіть туди:
   ```env
   GEMINI_API_KEY=ваш_ключ_тут
   ```
3. Скрипти автоматично виявлять ключ і перейдуть на прямі HTTPS-запити до Gemini API.

*Примітка:* Якщо ключ або клієнт `agy` не знайдені, система автоматично перейде у резервний фоновий режим роботи (Autopilot self-loop) або запропонує копіювати пропозиції вручну через буфер обміну (Clipboard Mode).

### Чи можна працювати тільки в Gemini, без Claude?
Так, але як ручний запуск, а не встановлення: дайте агентній сесії Gemini (з доступом до файлів і терміналу) пряму вказівку —
> Clone https://github.com/ayukhno/autosound-tuning-skill, read `skills/autosound-tuning/SKILL.md`, and follow that method as your operating instructions for this session.

Механізму ковзного вікна там немає, тож на довгій сесії Gemini втрачає точність. Безкоштовний і передбачуваний варіант — **Варіант 4** зі списку вище: готові промпти для [Google AI Studio](https://aistudio.google.com/) на гілці [manual_step-by-step](https://github.com/ayukhno/autosound-tuning-skill/tree/manual_step-by-step).

## Проведення замірів

### Вимірювання фази: XLR-мікрофони проти USB (UMIK-1/2)
- **XLR-мікрофони (Behringer ECM8000, Beyerdynamic MM1 тощо):** Підключаються через зовнішню звукову карту. Дозволяють використовувати **фізичний кабель зворотного зв'язку (loopback)** — дріт, що з'єднує вихід карти з її вільним входом. Це дає комп'ютеру апаратний, абсолютно стабільний відлік часу старту заміру з точністю до одного семпла.
- **USB-мікрофони (UMIK-1 / UMIK-2):** Підключаються напряму до USB-порту. Не мають аналогового входу, тому фізичний кабель loopback підключити неможливо.

### Чи можна виміряти фазу на UMIK-1?
**Так.** Для отримання точних даних фази використовуйте в REW функцію **Acoustic Timing Reference (акустичний відлік часу)**. Перед початком кожного заміру звукова карта відтворює короткий сигнал («чірп») через один обраний динамік (зазвичай це найближчий до мікрофона твітер), який виступає нульовою точкою відліку часу для вимірюваного каналу.

Детальне налаштування REW для USB-мікрофонів дивіться у відеоуроці: [Measuring Speaker Phase in REW](https://www.youtube.com/watch?v=El-kwZ5_nnU).

> [!WARNING]
> **Знімайте всі виміри безперервно за один раз і обов'язково переміряйте перший динамік наприкінці сесії.**
> * **Температурний дрейф повітря руйнує точність.** Швидкість звуку залежить від температури повітря в салоні. Зміна температури всього на кілька градусів зміщує час прильоту сигналу на частки мілісекунди. Це критично для фазового зведення СЧ та ВЧ-динаміків на частотах кросовера.
> * **Зсув накопичується від запусків замірів.** Один динамік, виміряний 6 разів поспіль протягом 18 хвилин, змістив час прильоту звуку на один семпл (10 мікросекунд, що еквівалентно зміщенню мікрофона на ~3.6 мм). При цьому 17 хвилин простого очікування змістили час лише на 0.5 мікросекунди, тоді як кожне наступне активне вимірювання додавало близько 2.6 мікросекунди зсуву.
> * **Обов'язково робіть перевірочний замір першого динаміка наприкінці сесії.** Контроль захвату у версії 3.x автоматично порівняє ці два виміри з точністю до часток семпла і просто відхилить всю серію замірів, якщо виявить небезпечний температурний або системний зсув часу.

### Правила іменування замірів у REW
Розрахункові інструменти шукають потрібні графіки виключно за їхніми назвами в REW:

- `m-L_01 (sw)` — канал `m-L` (лівий середньочастотник/мідрейндж), раунд вимірювань `01`, свіп (sweep).
- `m-L_01 (rta)` — замір у русі (RTA, moving-mic average) для цього ж динаміка.
- `sw_01 (sw)`, `w-R_01 (sw)`, `tw-L_01 (sw)` — сабвуфер, правий мідбас, лівий твітер відповідно.
- `L_01 (rta)`, `ALL_01 (rta)` — сумарний RTA-замір усієї лівої сторони або всієї системи разом.
- `m-L p5_01 (sw)` — замір динаміка в окремій контрольній точці простору `p5` (допускається також назва `m-L_01 (sw) p5`).
- `m-L-ctl1_01 (sw)` і `m-L-ctl3_01 (sw)` — контроль часу: перший відкриває серію замірів динаміка, другий її закриває (в авті ті самі два можна набрати як `m-L_01ctl` і `m-L_01rep`).
- `m-L_final (sw)` — перевірочний замір після фіксації параметрів.

Повна схема проведення замірів та їхня черговість описані у файлі [`references/phases/capture-session-sheet.md`](skills/autosound-tuning/references/phases/capture-session-sheet.md).

### Сесія зйомки (Capture): чому тільки захисні фільтри?
**REW має бути відкритим увесь час роботи:** скіл читає заміри з живого вікна через API, а не з експортованих файлів.

Сесія зйомки — це вимірювання кожного динаміка окремо із застосуванням у DSP **виключно захисних фільтрів** (High-Pass / HPF для СЧ та ВЧ на безпечній частоті, щоб вони не згоріли під час гучного свіпу). Жодних робочих кросоверів, затримок чи еквалайзера вмикати не можна — нам потрібен чистий акустичний відгук динаміка в салоні. Математичні скрипти автоматично «віднімуть» вплив захисного фільтра перед розрахунком робочої фільтрації, що забезпечить ідеальну точність зведення фаз.

*Важливо:* Вимикайте звук (Mute) на всіх інших каналах процесора напряму через його софт, тримайте стабільний рівень гучності карти та магнітоли протягом усього вимірювання.

### Навіщо потрібні позиції p1…p9 та контроль часу ctl?
- **Визначення природи провалів та піків:** Резонанси динаміків залишаються нерухомими на графіку при зміщенні мікрофона на кілька сантиметрів (їх можна правити еквалайзером). Акустичні провали через відбиття звуку від скла чи сидінь хаотично зміщуються по частоті (їх підсилювати марно і небезпечно, тому ШІ ігнорує такі зони).
- **Розрахунок добротності (Q):** Розкид замірів у точках `p1…p9` навколо голови слухача дозволяє розрахувати безпечну межу добротності фільтрів еквалайзера.
- **Контроль часового зсуву:** Повторні заміри центру `ctl` дозволяють математично зафіксувати реальний дрейф часу системи в процесі роботи.

## Цільові криві (Target Curves)

### Як створити та налаштувати власну цільову криву?
Єдиної «правильної» кривої не існує — це ваша первинна робоча гіпотеза, яку ви коригуватимете на слух.

1. **Замовте розрахунок у ШІ:** Опишіть свої улюблені жанри музики, стиль прослуховування, побажання щодо відомих кривих порівняння (наприклад: *"візьми за основу ResoNix Accurate, але додай 2 дБ глибини на сабвуфері та зроби високі частоти трохи м'якшими"*) чи скарги на звук (*ріже вухо, мало повітря, гуде*). Скрипт автоматично згенерує файл кривої, збереже його в папку проєкту та побудує цільові графіки для кожного динаміка.
2. **Намалюйте вручну:** Перейдіть на безкоштовний сайт **Nono Tuning Tool** ([nonotuningtool.com](https://nonotuningtool.com) → *Custom Target Curve*), намалюйте графік мишкою, експортуйте `.txt` файл та закиньте його в папку вашого проєкту.
3. **Порівняйте на графіках:** Скористайтеся нашим зручним візуалізатором:
   **[Відкрити візуалізатор цільових кривих онлайн](https://ayukhno.github.io/autosound-tuning-skill/_curve-visualizer.html?lang=uk)**. Тут можна порівняти вашу криву side-by-side з відомими стандартами SQ-Comp-Ref, ResoNix, Audiofrog, Harman, Jazzi чи Whitledge. Клікніть правою кнопкою миші на будь-яку точку графіка, щоб отримати підказку про тональний характер цієї зони.

## Проєкт на диску та DSP

### Структура папки проєкту та резервне копіювання
Одна папка містить весь опис вашої системи:
- `project.json` — динаміки, виходи процесора, профіль DSP, опис мікрофона та активна цільова крива.
- Реєстр версій налаштувань (`registry.json`) — повна упорядкована історія кросоверів, затримок та фільтрів еквалайзера.
- `process-state.json` — опис поточного кроку роботи та перевірених замірів.
- `autosound_context.md` та текстовий журнал — індивідуальні нотатки та слухові вердикти.
- Цільові криві та готові файли експорту налаштувань для DSP.

*Резервна копія:* Обов'язково зберігайте ці невеликі текстові та json-файли. Великі файли замірів REW `.mdat` копіювати необов'язково. Інсталятор пропонує налаштувати автоматичне приватне резервне копіювання на GitHub.

### Сумісність із процесорами та імпорт фільтрів у DSP
Скіл розраховує параметри фільтрів та записує їх у файл:
- **Audiotec Fischer (Helix / MATCH / BRAX):** Генерується готовий файл Full EQ, який офіційна програма DSP PC-Tool імпортує повністю в один клік для всіх каналів відразу.
- **Інші процесори:** Створюється файл у стандартному сумісному форматі REW Generic (до 20 смуг еквалайзера) або його розширена версія. Для перенесення параметрів вручну використовуйте зручний софт автоматизації: [REW-EQ-CopyPaste-Assistant](https://github.com/IvanBakhmutov/REW-EQ-CopyPaste-Assistant).
- **Перевірка параметрів:** Система перед генерацією файлів завжди перевіряє фільтри на відповідність реальним технічним лімітам вашого процесора (кількість смуг, частота дискретизації, типи фільтрів).

### Робота з пасивними кросоверами (твітер + СЧ на одному каналі)
Пара на пасивному кросовері — це для методу **один канал**: один замір, одна затримка, один гейн, один набір смуг EQ. Усе інше працює як звичайно, і сумарний графік буде чесним, включно з провалом у зоні пасивного розділу. Чого не зробить ніякий софт іззовні — не зведе твітер із СЧ **усередині** пари й не зрушить точку пасивного розділу: для цього потрібна поканалка.
