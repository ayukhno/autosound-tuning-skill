## Вибір шляху

### Чотири варіанти використання

* 🖥️ **Варіант 1 · Версія 3.x у графічному вікні (Autosound TCC)**
  Найбільш автоматизований та наочний шлях. Інсталятор налаштовує Claude Code, Python, ядро методу, графічний інтерфейс та автоматичного ШІ-критика.
  * **Вимоги:** macOS або Windows, платний Claude Pro/Max, бета-версія REW з увімкненим API, ~700 МБ вільного місця.
  * **Переваги:** Ви бачите дерево системи, графіки замірів, покроковий план та вікно чату в єдиному зручному інтерфейсі. Стан зберігається автоматично, будь-яку дію в реєстрі версій можна скасувати в один клік.
  * **Недоліки:** Графічний застосунок є досить молодим і наразі перебуває в стані бета-тесту.

* 💻 **Варіант 2 · Версія 3.x у терміналі**
  Те саме сучасне ядро та рівень автоматизації, але взаємодія відбувається виключно через текст у консолі. Встановлюється через інсталятор із прапорцем `--terminal`.
  * **Вимоги:** Ті самі підписки та REW з API, але без графічної оболонки.
  * **Переваги:** Максимальна швидкість роботи, мінімальне споживання системних ресурсів. Проєкти повністю сумісні з графічною програмою TCC (ви зможете відкрити ту саму папку в інтерфейсі пізніше).

* 🏆 **Варіант 3 · Лінійка 2.x (Перевірений чемпіон)**
  Стабільний плагін для Claude Code, жорстко зафіксований на версії `v2.8.3` (гілка `2.x`). Саме цим алгоритмом налаштоване авто автора взяло чотири нагороди EMMA та AYA у 2026 році.
  * **Вимоги:** Платний Claude Pro, бета-версія REW з API, робота в терміналі.
  * **Переваги:** Перевірений часом та змаганнями надійний алгоритм. Отримує лише критичні виправлення помилок (багфікси), нові функції сюди навмисно не додаються.
  * **Недоліки:** Немає автоматичного контролю станів машиною (все ведеться вручну у текстових Markdown-файлах), немає методу «Спочатку за столом» та сучасних розрахункових утиліт.

* 🌐 **Варіант 4 · Веб-чат (Без встановлення програм)**
  Повністю ручний покроковий процес налаштування за допомогою гілки [manual_step-by-step](https://github.com/ayukhno/autosound-tuning-skill/tree/manual_step-by-step).
  * **Вимоги:** Безкоштовний сервіс Google AI Studio або будь-який веб-чат з ШІ на ваш вибір.
  * **Переваги:** Абсолютно безкоштовно. Не потребує встановлення жодного софту чи інструментів розробника на ваш комп'ютер. Ідеально для ознайомлення з логікою методу.
  * **Недоліки:** Кожен крок виконується суто вручну (копіювання промптів, самостійний експорт текстових файлів з REW), немає інтеграції через API та автоматичної перевірки розрахунків локальними скриптами.

### Який варіант обрати?

* **Бажаєте максимум автоматизації та графіку:** Оберіть **Варіант 1 (TCC)**.
* **Віддаєте перевагу консолі без зайвого софту:** Оберіть **Варіант 2 (3.x Terminal)**.
* **Шукаєте перевірену часом чемпіонську стабільність:** Оберіть **Варіант 3 (2.8.3)**.
* **Хочете безкоштовно протестувати логіку методу:** Оберіть **Варіант 4 (веб-чат)**.

> [!NOTE]
> Ви не затиснуті в межах одного рішення: проєкти лінійки 3.x без проблем відкриваються як у консолі, так і у графічній програмі TCC, а перехід зі старої версії 2.x на 3.x повністю автоматизований.

### Як визначити вже встановлену версію?

* **За командою, яку ви вводили:** Якщо ви встановлювали плагін командою `/plugin install autosound-tuning` всередині Claude Code — у вас версія **2.x**. Якщо ви запускали скрипт встановлення в один рядок (`curl … | bash` або `irm … | iex`) — у вас версія **3.x**.
* **За вмістом папки проєкту:** Якщо папка містить файл `dsp-state-current.md` — це проєкт **2.x**. Якщо папка містить машинні файли `project.json` та `process-state.json` — це проєкт **3.x**.
* **Через інтерфейс застосунку:** У програмі TCC перейдіть у меню *Diagnostics → Installation*.

---

### Як залишитися на стабільній лінійці 2.x

Звичайне автоматичне оновлення плагінів не переведе вас на 3.x примусово. Проте, якщо ви хочете повністю зафіксувати версію та локально контролювати процес отримання багфіксів для гілки 2.x, клонуйте репозиторій самостійно:

```bash
git clone -b 2.x https://github.com/ayukhno/autosound-tuning-skill.git ~/autosound-2x
```

Після цього всередині Claude Code виконайте наступні дві команди:
```bash
/plugin marketplace add ~/autosound-2x
/plugin install autosound-tuning
```
Тепер ваш плагін посилається на локальну папку. Ви зможете оновлювати його за потреби простою командою `git -C ~/autosound-2x pull`.

---

### Перехід з 2.x на 3.x

У системі може бути активний лише один такий плагін одночасно. Перед встановленням версії 3.x обов'язково видаліть стару версію 2.x всередині Claude Code:

```
/plugin uninstall autosound-tuning
/plugin marketplace remove autosound-tuning-skill
```

Після встановлення нової версії 3.x ви можете імпортувати поточний стан автомобіля (активні кросовери, затримки, гейни, еквалайзер та профіль DSP) у новий формат за допомогою автоматичного мігратора:

```sh
python3 ~/.claude/skills/.autosound-tuning-src/skills/autosound-tuning/rew_tool/state/migrate.py <шлях-до-старого-проєкту> --into <шлях-до-нового-проєкту>
```

### Головні зміни в 3.x

* 📦 **Проєкт як структура даних:** Усі параметри системи зберігаються у файлах `project.json` та `process-state.json`. ШІ зчитує точні машинні факти, а не намагається згадати їх із текстової історії діалогу.
* 🛋️ **Метод «Спочатку за столом»:** Замість багатьох поїздок до авто — **один захід на повну акустичну зйомку** (фаза 0) і **один короткий на перевірку** (фаза 3). Уся аналітика між ними — розрахунок частот зрізу, зведення фаз, еквалайзер — робиться за столом на передбаченій сумі ваших же замірів.
* 🧮 **Математична верифікація:** Спеціальні локальні скрипти аналізують графіки за критерієм мінімальних фазових втрат, обмежують добротність (Q) еквалайзера на основі розкиду точок замірів та автоматично виявляють часовий зсув мікрофона.
* 🛑 **Автоматичні відмови:** Якщо вхідні заміри суперечливі, мікрофон дав велику часову похибку або виміряно не всі канали — система зупинить розрахунки та відхилить раунд замість видачі неточного чи небезпечного результату.

## Філософія та архітектура: навіщо тут ШІ?

### Місія та концепція

Ми створюємо **інтелектуальний екзоскелет** для налаштування звуку. Людина (Арбітр) завжди залишається головною ланкою — вона слухає систему, оцінює глибину, висоту та стабільність звукової сцени і приймає остаточні рішення. 

ШІ бере на себе рутинні обчислення та фізику кабіни: аналізує фази, прораховує точні затримки на стиках смуг та керує програмою REW через її API, звільняючи ваш час для творчого прослуховування музики.

---

### Чому це спеціалізований скіл, а не звичайний чат?

* **Усунення втрати пам'яті (memory drift):** Будь-який стандартний чат з ШІ після кількох годин спілкування починає забувати початкові значення, плутати гейни чи частоти зрізу кросоверів. Наша система зберігає поточний стан проєкту у файлі `project.json` на вашому диску. ШІ перечитує цей файл при кожному новому запиті — його пам'ять не «згадується», а надійно зчитується з диска.
* **Спеціалізована база знань:** Скіл містить жорсткі правила безпеки для захисту твітерів, алгоритми фазового зведення, готові цільові криві та логіку аналізу салону авто, про які загальні моделі ШІ навіть не здогадуються.
- **Локальна обробка через REW API:** Сирі дані замірів (тисячі точок на один графік) обробляються локальними Python-скриптами за мілісекунди. ШІ отримує в чат лише лаконічне математичне резюме, що виключає помилки ручного копіювання чисел та економить ваші кошти.

### Карта налаштування: фази −1…5 та підхід «Спочатку за столом»

| Фаза | Де відбувається | Що саме виконується | Результат етапу |
| :--- | :--- | :--- | :--- |
| **−1 Підготовка** | за столом | Введення параметрів авто, динаміків, можливостей DSP та вибір цільової кривої. | Створення файлу `project.json` та конфігурації. |
| **0 Зйомка** | в авто (1 раз) | Замір кожного динаміка окремо із **захисними** фільтрами (HPF); свіпи та RTA заміри в русі. | Один якісний та перевірений пакет замірів (раунд). |
| **1 Основа** | за столом | Розрахунок частот зрізу кросоверів, гейнів, затримок та полярності на основі прогнозування суми фаз. | Базове налаштування системи в реєстрі версій. |
| **2 Еквалайзер** | за столом | EQ приходить **пакетами**: резонанси драйвера → форма ліво/право → тон до цілі. За замовчуванням лише зрізи, до 6 смуг на канал. Кожен пакет — одне рішення «так/ні» й одна версія в реєстрі. | Готові файли експорту налаштувань для вашого DSP. |
| **3 Вердикт** | в авто (коротко) | Введення чисел у DSP. Контроль введеного автоматично перевіряє, чи дійсно реальні заміри авто збігаються з математичним прогнозом. | Повністю зафіксоване та перевірене технічне налаштування. |
| **4 Слухання** | в авто | Тестові треки (EMMA/AYA, CarMus, Chesky) і шпаргалка «на що слухати». Якщо щось гуде чи ріже вухо — скіл створює список підозрюваних і править по одній смузі з A/B (до 3 кіл). | Живі слухові вердикти, прив'язані до версій. |
| **5 Варіації** | за столом/в авто | Налаштування додаткових пресетів (під різні жанри, центральний канал тощо) без зміни технічної основи. | Додаткові пресети звуку в системі. |

> [!NOTE]
> Якщо реальні виміри в автомобілі на Фазі 3 розходяться з математичним прогнозом, система автоматично відкотить крок назад і перейде до класичного покрокового ітеративного алгоритму.

### Що метод категорично відмовляється робити?

* **Записувати налаштування напряму у ваш DSP** — введення параметрів завжди залишається за вами.
* **Рахувати затримки за одним заміром** — потрібно мінімум 4 незалежні оцінки часу прильоту звуку.
* **Підсилювати звук у зонах фазових провалів (акустичних нулів)** — такий провал викликає інтерференція хвиль у салоні, а не динамік. Заповнити його підсиленням **неможливо в принципі**: у точці слухача нічого не зміниться, а динамік та підсилювач будуть перевантажені. Провал, який підняти можна, від нуля надійно відрізняє тест надлишкової фази (*Excess phase* у REW) — підіймається лише перша.
* **Працювати з неякісними замірами** — виявлений температурний зсув мікрофона або відсутність захисних фільтрів призведуть до миттєвого відхилення всього раунду вимірів.

## Проведення замірів

### Вимірювання фази: XLR-мікрофони проти USB (UMIK-1/2)

* **XLR-мікрофони (Behringer ECM8000, Beyerdynamic MM1 тощо):** Підключаються через зовнішню звукову карту. Дозволяють використовувати **фізичний кабель зворотного зв'язку (loopback)** — дріт, що з'єднує вихід карти з її вільним входом. Це дає комп'ютеру апаратний, абсолютно стабільний відлік часу старту заміру з точністю до одного семпла.
* **USB-мікрофони (UMIK-1 / UMIK-2):** Підключаються напряму до USB-порту. Не мають аналогового входу, тому фізичний кабель loopback підключити неможливо.

---

### Чи можна виміряти фазу на UMIK-1?

**Так.** Для отримання точних даних фази використовуйте в REW функцію **Acoustic Timing Reference (акустичний відлік часу)**. Перед початком кожного заміру звукова карта відтворює короткий високочастотний сигнал («чірп») через один обраний динамік (зазвичай це найближчий до мікрофона твітер), який виступає нульовою точкою відліку часу для вимірюваного каналу.

Детальне налаштування REW для USB-мікрофонів дивіться у відеоуроці: [Measuring Speaker Phase in REW](https://www.youtube.com/watch?v=El-kwZ5_nnU).

> [!WARNING]
> **Знімайте всі виміри безперервно за один раз і обов'язково переміряйте перший динамік наприкінці сесії!**
> * **Температурний дрейф повітря руйнує точність:** Швидкість звуку залежить від температури повітря в салоні. Зміна температури всього на кілька градусів зміщує час прильоту сигналу на частки мілісекунди. Це критично для фазового зведення СЧ та ВЧ-динаміків на частотах кросовера.
> * **Зсув накопичується безпосередньо від запусків замірів:** Один динамік, виміряний 6 разів поспіль протягом 18 хвилин, змістив час прильоту звуку на один семпл (10 мікросекунд, що еквівалентно зміщенню мікрофона на ~3.6 мм). Зсув залежав від запусків замірів, а не просто часу очікування.
> * **Обов'язково робіть перевірочний замір першого динаміка наприкінці сесії:** Контроль захвату у версії 3.x автоматично порівняє ці два виміри з точністю до часток семпла і просто відхилить всю серію замірів, якщо виявить небезпечний температурний або системний зсув часу.

---

### Правила іменування замірів у REW

Розрахункові інструменти шукають потрібні графіки виключно за їхніми назвами в REW:

* `m-L_01 (sw)` — канал `m-L` (лівий середньочастотник/мідрейндж), раунд вимірювань `01`, свіп (sweep).
* `m-L_01 (rta)` — замір у русі (RTA, moving-mic average) для цього ж динаміка.
* `sw_01 (sw)`, `w-R_01 (sw)`, `tw-L_01 (sw)` — сабвуфер, правий мідбас, лівий твітер відповідно.
* `L_01 (rta)`, `ALL_01 (rta)` — сумарний RTA-замір усієї лівої сторони або всієї системи разом.
* `m-L p5_01 (sw)` — замір динаміка в окремій контрольній точці простору `p5` (допускається також назва `m-L_01 (sw) p5`).
* `m-L-ctl1_01 (sw)` і `m-L-ctl3_01 (sw)` — контроль часу: перший відкриває серію замірів динаміка, другий її закриває (в автомобілі ті самі два заміри можна набрати як `m-L_01ctl` і `m-L_01rep`).
* `m-L_final (sw)` — перевірочний замір після фіксації параметрів.

Повна схема проведення замірів та їхня черговість описані у файлі [`references/phases/capture-session-sheet.md`](skills/autosound-tuning/references/phases/capture-session-sheet.md).

### Сесія зйомки (Capture): чому тільки захисні фільтри?

> [!IMPORTANT]
> **REW має бути відкритим увесь час роботи:** скіл зчитує заміри з живого вікна програми через API, а не з експортованих файлів на диску.

Сесія зйомки — це вимірювання кожного динаміка окремо із застосуванням у DSP **виключно захисних фільтрів** (High-Pass / HPF для СЧ та ВЧ на безпечній частоті, щоб вони не згоріли під час гучного свіпу). Жодних робочих кросоверів, затримок чи еквалайзера вмикати не можна — нам потрібен чистий акустичний відгук динаміка в салоні автомобіля. Математичні скрипти автоматично «віднімуть» вплив захисного фільтра перед розрахунком робочої фільтрації, що забезпечить ідеальну точність зведення фаз.

*Важливо:* Вимикайте звук (Mute) на всіх інших каналах процесора напряму через його софт, тримайте стабільний рівень гучності карти та магнітоли протягом усього вимірювання.

---

### Навіщо потрібні позиції p1…p9 та контроль часу ctl?

* **Визначення природи провалів та піків:** Резонанси динаміків залишаються нерухомими на графіку при зміщенні мікрофона на кілька сантиметрів (їх можна правити еквалайзером). Акустичні провали через відбиття звуку від скла чи сидінь хаотично зміщуються по частоті при русі мікрофона — їх підсилювати марно і небезпечно, тому ШІ ігнорує такі зони.
* **Розрахунок добротності (Q):** Розкид замірів у точках `p1…p9` навколо голови слухача дозволяє розрахувати безпечну межу добротності фільтрів еквалайзера.
* **Контроль часового зсуву:** Повторні заміри центру `ctl` дозволяють математично зафіксувати реальний дрейф часу системи в процесі роботи.

## Цільові криві (Target Curves)

### Як створити та налаштувати власну цільову криву?

Єдиної «правильної» кривої не існує — це ваша первинна робоча гіпотеза, яку ви коригуватимете на слух після отримання базового налаштування.

1. **Замовте розрахунок у ШІ:** Опишіть свої улюблені жанри музики, стиль прослуховування, побажання щодо відомих кривих порівняння (наприклад: *"візьми за основу ResoNix Accurate, але додай 2 дБ глибини на сабвуфері та зроби високі частоти трохи м'якшими"*) чи скарги на звук (*ріже вухо, мало повітря, гуде*). Скрипт згенерує файл кривої, збереже його в папку проєкту та побудує цільові графіки для кожного динаміка.
2. **Намалюйте вручну:** Перейдіть на безкоштовний сайт **Nono Tuning Tool** ([nonotuningtool.com](https://nonotuningtool.com) → *Custom Target Curve*), намалюйте графік мишкою, експортуйте `.txt` файл та закиньте його в папку вашого проєкту.
3. **Порівняйте на графіках:** Скористайтеся нашим зручним візуалізатором:
   **[Відкрити візуалізатор цільових кривих онлайн](https://ayukhno.github.io/autosound-tuning-skill/_curve-visualizer.html?lang=uk)**. Тут можна порівняти вашу криву side-by-side з відомими стандартами SQ-Comp-Ref, ResoNix, Audiofrog, Harman, Jazzi чи Whitledge. Клікніть правою кнопкою миші на будь-яку точку графіка, щоб отримати підказку про тональний характер цієї зони.

## Проєкт на диску та DSP

### Структура папки проєкту та резервне копіювання

Одна папка на вашому диску містить повний опис вашої аудіосистеми:

| Файл | Що містить | Навіщо потрібен |
| :--- | :--- | :--- |
| **`project.json`** | Базова конфігурація системи | Канали динаміків, виходи DSP, профіль процесора, опис мікрофона та активна цільова крива. |
| **`registry.json`** | Реєстр версій налаштувань | Повна впорядкована історія кросоверів, затримок, гейнів та фільтрів еквалайзера. |
| **`process-state.json`** | Поточний технічний стан | Опис поточної активної фази роботи та перевірених замірів. |
| **`autosound_context.md`** | Словник та контекст автомобіля | Індивідуальні нотатки, особливості салону та ваші слухові оцінки. |
| **`*.txt` / `*.json`** | Цільові криві та файли імпорту | Файли налаштувань для завантаження в DSP та файли кривих для REW. |

> [!IMPORTANT]
> **Обов'язково зберігайте ці невеликі текстові та JSON-файли.**
> Великі файли замірів REW `.mdat` (від 16 до 112 МБ кожен) копіювати необов'язково. Наш інсталятор пропонує налаштувати автоматичне безкоштовне приватне резервне копіювання папки проєкту на GitHub.

### Сумісність із процесорами та імпорт фільтрів у DSP

Скіл розраховує параметри фільтрів та записує їх у файл:

* **Audiotec Fischer (Helix / MATCH / BRAX):** Сімейство, на якому безпосередньо розроблявся та тестувався цей метод. Генерується готовий файл Full EQ, який офіційна програма DSP PC-Tool імпортує повністю в один клік для всіх каналів відразу.
* **Інші процесори:** Створюється файл у стандартному сумісному форматі REW Generic (до 20 смуг еквалайзера) або його розширена версія. Для автоматизації ручного введення параметрів використовуйте зручний безкоштовний інструмент: [REW-EQ-CopyPaste-Assistant](https://github.com/IvanBakhmutov/REW-EQ-CopyPaste-Assistant).
* **Перевірка параметрів:** Система перед генерацією файлів завжди перевіряє фільтри на відповідність реальним технічним лімітам вашого процесора (кількість смуг, частота дискретизації, типи фільтрів).

### Робота з пасивними кросоверами (твітер + СЧ на одному каналі)

Пара динаміків на пасивному кросовері сприймається системою як **один цілісний канал**: вона отримує один замір, одну затримку, загальний гейн та один набір смуг еквалайзера. 

Усе інше працює як звичайно, і сумарний графік буде чесним, включно з провалом у зоні пасивного розділу, якщо він присутній. Чого не здатна зробити жодна програма у світі ззовні — це налаштувати затримки або звести фазу між СЧ та ВЧ **всередині** цієї пасивної пари: для цього потрібне поканальне підключення.
