# REW API — Pulling Data & Python Tooling

This document outlines how to interact with Room EQ Wizard (REW) via its API and describes the structure of the built-in Python tools available in this skill.

## API Connectivity

REW exposes its API at `localhost:4735`, reachable **from the host where Claude/Gemini run** — pull data live, no port-forwarding.

> [!NOTE]
> **Setup-dependent workflow:** If the DSP's software runs on a different OS/VM than REW (e.g., REW on macOS + the Helix PC-Tool in a Parallels Windows VM), there's **one courier step** — handing the REW EQ export to the DSP via a shared folder; a native same-OS DSP tool skips even that.

---

## Tool Directory Layout

The Python tool ships **inside this skill** at `<skill-dir>/rew_tool/` (uses standard library only — no external dependencies, no project data). The modules import flat, so run it from its own directory:
```bash
cd <skill-dir>/rew_tool && python3 rew_tool.py ...
```
Or add `<skill-dir>/rew_tool` to your `PYTHONPATH`.

### Module Overview

* **`rew_tool/rew_api.py`**
  * `get_measurements`, `get_fr`, `get_group_delay`, `get_impulse_response`, `get_distortion`
  * `get_filters`/`set_filters`, `get_equaliser`/`set_equaliser`
  * `get_crossover_types`, `get_slopes`
  * `get_target_settings`/`response`
  * `find_measurement_id(name)` / `get_measurement_by_name(name)` — **resolve title ↔ id FRESH before every pull** (never use a cached index)
  * **Measurement-processing (free, not Pro-gated — `POST /measurements/{id}/command`):** `excess_phase_version(mid)` / `minimum_phase_version(mid)` create the `-EP`/`-MP` versions (read excess phase back via `get_fr` — the authoritative min-vs-non-min decision, REW's own Hilbert); `set_smoothing(mid, '1/6')` applies REW's own smoothing before a pull; `measurement_command(mid, cmd, params)` is the low-level entry.
* **`rew_tool/analysis.py`**
  * FR/phase/IR/GD analysis + PEQ suggestions
  * `first_arrival` (leading-edge, not the global peak) + `relative_delay_xcorr` (L ↔ R delay, shape-robust)
  * Verify setup: `python3 analysis.py --selftest`
* **`rew_tool/joint_analysis.py`** — within-session summation / TA / phase decisions (magnitude-safe where in-cabin phase is not trustworthy)
  * **Quality / drift:** `flag_remeasure_candidates` (pre-echo vs the CLEANEST version of the SAME driver → which sweeps to redo), `timing_drift_audit` (Δstart vs waveform xcorr → REW label-drift vs a real TA change), `impulse_polarity` (leading-edge sign)
  * **Classify:** `joint_summation_check` (measured pair vs incoherent power ref → phase cancellation vs tonal dip; never boost a null), `phase_trust_gate` (do the complex solos reproduce the pair? if not, BLOCK delay/APF/polarity)
  * **Correct (drift-immune, relative):** `align_by_summation` (polarity + relative delay maximizing the coherent sum = the TA you can enter in the DSP), `allpass_for_residual_null` (2nd-order APF F/Q on the residual), `shelf_vs_bell` (broad tilt = shelf, gentler phase; else keep the bell)
  * `perceptual_smooth`, `midband_level_anchor`, `shape_deviation`. Verify: `python3 joint_analysis.py --selftest`
* **`rew_tool/xover_select.py`** — crossover-realization + joint-alignment API distilled from the v3 acoustic-target experiment (the rules live in `filter-types-car-audio.md` §Acoustic-plan-first)
  * `realize_driver` (acoustic target → electrical XO + trim + EQ, boost-budgeted), `select_neighbor_pair` (adjacent bands as a PAIR by acoustic-sum quality — per-driver-optimal picks can leave a >10 dB pair hole), `align_joint` (analytic delay/polarity; near-ties resolve ACROSS both polarities by smallest `|tau|`, an exact draw stays **non-inverted** by convention, and **`polarity_margin_db`** reports how far the chosen polarity beat the other — below a few tenths summation did not decide it. No "prefer non-inverted" margin: at an odd-order LR joint the inverted connection is correct and at 36 dB/oct leads by only 0.17 dB), `repair_joint_apf` (APF2 tried on BOTH branches; may return None when delay already absorbs a low-Q rotation; **`robust=True` default** — scores by the jitter-robust worst null per `diagnostic §24`, `robust=False` only to reproduce legacy razor runs), `repair_joint_apf_multi` (several same-day snapshots of the joint → selection by **MIN of the robust score across snapshots**; field lesson: even robust single-snapshot optima didn't transfer across an hour; returns `per_snapshot_db`), `lr_phase_tracking` (the L/R acoustic-symmetry metric)
  * `dsp_math.robust_worst_null` + `ROBUST_PERT` (±20 µs / ±0.5 dB) — THE objective for any joint-phase decision; `apf_search(robust=…)` underneath
  * deps: numpy + **scipy** (via `dsp_math.py`); fixed fs=96 kHz. Verify: `python3 xover_select.py --selftest`
* **`rew_tool/flaw_map.py`** — the acoustic flaw map as a command: features from `curve_view`, stays/moves from `ellipsoid`, minimum-phase from the excess-phase gate → rows for `acoustics.flaws` (driver_resonance/notch, modal_peak/notch, cabin_null/no_boost, non_min_phase/no_boost), all as `hypothesis` with evidence, through `project.add_flaw` (replaces, never twins). Everything it does not write it lists with the reason — a dip above Schroeder, narrower than 1/6 oct, a peak that moves, a region where the RAW record has no signal (the de-embedded quotient there is noise wearing the driver's shape). Verify: `python3 flaw_map.py --selftest`.
* **`rew_tool/xover_candidates.py`** — 2–3 crossover candidates for one driver from `xover_select.realize_driver`, DESCRIBED: fit, level and phase at each corner (the family's definition is the anchor: LR −6.02, BW −3.01), phase turn across the corner octave, group delay added against Blauert & Laws, the corner's margin from the driver's own −6 dB edge read off its solo, junction cost, Fs margin with `--fs`. It never picks — the last line says so. Verify: `python3 xover_candidates.py --selftest`.
* **`rew_tool/setup_import.py`** — the DSP's CURRENT setup into the ledger, honestly: a transcription typed from the screens (a Helix has no text export), validated against the DSP profile — delay grid and ceiling, gain range and step, EQ types, band count and ranges — each violation a refusal by name, never a rounding; EQ from an ATF bank (`--atf code=file`) where one exists; the version carries `provenance: transcription, verified_by_file=false`. First write seeds the ledger, later ones go through `apply.propose`. Verify: `python3 setup_import.py --selftest`; walked by `path_check` 1.5.
* **`rew_tool/crossover_checks.py`** — the three questions asked of a corner before it is entered: Fs margin (floor 1.1× installed Fs = doctrine, REFUSE; working margin = convention, CAUTION, relaxes with order), group-delay budget (Blauert & Laws 1978 — external, quoted and named as such), junction cost (ISO 226 through `equal_loudness`, so the 2–4 kHz answer is derived rather than asserted). Verdicts OK / CAUTION / REFUSE, each with its source. stdlib. Verify: `python3 crossover_checks.py --selftest`
* **`rew_tool/dsp_math.py`** — REW-exact filter math shared by `xover_select` (BU/BE/L-R crossovers — scipy Bessel with `norm="mag"`; PK/LS_Q/HS_Q ≡ RBJ; `apf2_response` hardware-verified on the Helix Ultra S, `helix-phase-allpass.md`; **`apf1_response(freqs, f0)`** — the 1st-order all-pass, −90° at `f0`, 0 → −180° overall, a pure 1/(π·f0) delay far below `f0`; the two share one convention, `apf1² ≡ apf2(Q 0.5)`). `eq_complex` dispatches by band kind — `PK`, `LS`/`LSH`, `HS`/`HSH`, `APF1`, `APF2` — and **refuses an unknown kind** instead of drawing it as a shelf (SCR-050). **`sum_loss(freqs, A, B, band, level_gate_db=None)`** — the junction metric ported from Resonalyze (MIT, `NOTICE.md`): per-bin `20·log10(|A+B| / (|A|+|B|))` ≤ 0, `avg_db` over LOG frequency (grid-independent), `dip_db`/`dip_hz` = the minimum of a 1/6-octave moving mean, `score_db = avg + 0.5·(dip − avg)`; `level_gate_db=25` is the READ-OUT form (a bin 25 dB under its local ±1-octave peak is NaN), `None` the SEARCH form. **`align_sum_loss(...)`** — the sum-loss twin of `align_delay_polarity`, returning `(pol, tau_ms, dip_db, polarity_margin_db, avg_db, score_db)` so both rulers print side by side (the user's rule: sum loss NEXT TO the worst null). Both twins pick among LOBES (local optima), never bare grid neighbours — the grid-point tie rule biased the energy twin toward zero by up to 0.04 ms (fixed 2026-08-24). Verify: `python3 dsp_math.py selftest`
* **`rew_tool/curve_view.py`** — the "three distances" discipline for reading any dB curve (a response, an L−R difference, a new-vs-old delta): `report(freqs, mag_db, band, source='sweep'|'mmm')` = band window → MACRO trend (1/3 oct ≈ critical band, band-anchored medians → voicing territory) → FINE residual (1/24 − macro) with detected features (FWHM width, extremum). **Every feature is ROUTED to the doctrine that owns it**: >2/3 oct → voicing (§6); <1/6 oct on a sweep → verify-first via MMM/mic-shift (§13); medium peak → point-EQ cut (§21/§2); medium dip → null-suspect, no boost until eq_gate/excess-phase clears it (§2/§13). `source='mmm'` skips the verify-first arm (already spatially averaged). Answers "what am I allowed to do about this?", not just "what is there". **⚠️ The FINE scale needs an UNSMOOTHED input.** REW returns the FR already smoothed (the payload carries `smoothing`, and `rew_api.set_smoothing` DEFAULTS to `1/6`); smoothing again here adds widths in quadrature and at `1/6` the fine residual collapses, so `find_features` reports a CLEAN system that is not — silently (fork session, live data, 2026-08-25). Pull the FR with `set_smoothing(mid, 'None')` before `get_fr`, or pass `input_smoothing=rew_api.fr_smoothing(mid)` to `report`/`multiscale` and it REFUSES (`CurveViewError`) rather than double-smoothing. MACRO is unaffected (1/24 input vs 1/3 macro = 1/2.99) and `macro_summary` stays usable on smoothed input. Verify: `python3 curve_view.py --selftest`
* **`rew_tool/eq_gate.py`** — measurement-driven EQ-**boost**-ability gate (the peak-vs-null doctrine, `diagnostic §2`, made quantitative). `ExcessPhaseGate(freqs, mag_db, excess_phase_deg, trust)` from a driver's sweep + REW's native excess-phase version (`rew_api.excess_phase_version`); `.check(f0, q)` → ALLOW / WARN (→ mic-shift cross-check, §13) / BLOCK; `.as_boost_gate()` plugs into `greedy_eq_fit(boost_gate=…)` / `realize_driver(boost_gate=…)`. Blocks only where a **deep local dip ∧ phase anomaly ∧ the filter delivers gain** coincide — phase alone over-blocks (cabin mids are phase-rough over 30-50 % of the band), depth alone can't tell cancellation from a fillable deficit. ⚠️ Calibration (Z 4.5/6.0, dip 4 dB) is **provisional — validated 7/7 on ONE build's boost history**; taste zones (de-esser) stay manual. Verify: `python3 eq_gate.py --selftest`
* **`rew_tool/spot_check.py`** — independent verification of a model's CITED numbers against live REW (driver-discipline §1.3; run it before applying a proposed package)
  * pair mode: levels at cited freqs + A−B deltas + actual band peak vs the **claimed** peak (flags a claim >1/12 oct off)
  * target mode: shape-anchored deviation vs a loaded target at cited freqs
  * `python3 spot_check.py "L_09 (rta)" "R_09 (rta)" --at 160,2540 --peak 2000-3000 --claim 2543.8` · `--selftest`
* **`rew_tool/target_curves.py`**
  * Handles loading and interpolating target curves.
* **`rew_tool/nono_curves.py`**
  * Parses Nono Tuning Tool curve exports:
    * `full` = `freq` & `mag`
    * `per-band` = `freq`, `mag`, & `phase`
* **`rew_tool/level_offsets.py`**
  * Preliminary per-channel LEVEL offsets from geometry (off-axis piston directivity + distance). Cut-only starting balance for Phase 1 §3.5, verified by RTA/ear. Inputs (distance/angle/piston radius/`n`) are project data. `--selftest`.
  * **`--solos DIR --ver N --levels-fixed [--project DIR]`** is the SECOND estimate — each channel's energy-averaged level in its own ledger band and the cut-only offsets that balance them; refuses (exit 3) without `--levels-fixed`, because no file records the volume knob. Where the two estimates disagree by more than a couple of dB, the disagreement is the finding. Walked by `path_check` 1.4.
* **`rew_tool/target_bands.py`**
  * Generates per-driver (per-band) target curves locally: house curve + crossovers + two-speaker summation offset + asymmetric L/R compensation + per-channel gains. Change a crossover → regenerate in one shot (no NTT-web round-trip). Phase 1 §5. `--selftest`, `--demo`.
* **`rew_tool/equal_loudness.py`**
  * Equal-loudness (ISO 226:2003) **sub-bass targeting**: a flat sub sounds bass-light because ear sensitivity at LF depends on listening level (Fletcher-Munson). Anchor to one measured sub freq+SPL → calibrate the phon contour → read per-freq target SPLs → `target − measured` = the EQ adjustment (cut-only + master up). Field-validated (helped win an AYA round). `--anchor F SPL --measure f=spl…`, `--selftest`.
* **`rew_tool/atf_eq.py`**
  * Parses and generates the Audiotec-Fischer (Helix) 30-band EQ bank (validated on real exports; parses an existing bank, formats and emits only the bands you decided).
* **`rew_tool/resonalyze_ir.py`** — REW loopback-referenced sweep → [Resonalyze](https://github.com/DIMOSUS/Resonalyze) impulse-response JSON (format v7, as the app saves it), so a REW-with-loopback set opens in its Virtual DSP / Auto delay / Auto crossover with nothing retyped. Pulls the **raw** IR (`?normalised=false` — the endpoint's default peak-normalises every IR to ±1.0 and destroys the level relation between channels), keeps the absolute time base by rotating the transfer IR so **sample 0 = the loopback reference** with an exact **fractional** shift (REW puts the mic-IR peak on an integer sample, so t = 0 lands at a fractional index; rounding would cost up to 0.5 sample = 1.8 mm), refuses anything not on the loopback base (`timingReference ≠ Loopback` or a timing offset), and validates every document with a port of the app's own `ImpulseResponseFile.Validate()`. Each file carries a `rewSource` block (title, uuid, REW date/delay, peak dBFS, the shift, the protective HPF in force) that their reader ignores. Protective high-passes are **not** removed (Resonalyze compensates at capture time; a file-based consumer must de-embed — say so in the manifest). Verified 2026-08-19: eight Passat files load through Resonalyze's reader verbatim and its `TimeAlignmentAnalysis` reads REW's delays back to ±0.01 ms. `--title "w-L_01 (sw)=w_L" … --out DIR [--hpf m_L=100:LR:24] [--process <project>/process] [--play-channel Left] [--sweep-seconds S]`; `--selftest`. Deps: numpy. **`--process`** fills each title's protective high-pass from the capture round recorded for its `_N` (`capture-protective`), so the manifest and the round are one fact with one home; an explicit `--hpf` that disagrees with the round is refused, and the manifest's `protectiveSource` says which it was.
* **`rew_tool/dsp_profile.py` — the bundled profile LIBRARY** (2026-08-23). `knowledge/dsp/profiles/` holds the method's reference DSP profiles, paired with that directory's prose by basename, and `find_bundled(vendor, model)` now defaults to it — it took a directory argument for months while the method shipped none, so every consumer built a private library and one processor ended up described four times in three serialisations. Deliberately NOT `community-inbox/dsp-profiles/`, which is a landing zone for other people's contributions. `list-bundled` enumerates it. **`refresh <project-dir> [--write]`** brings a project's `dsp_profile.json` back in line with the library — a command that can be re-run, not a paste that fixes today and diverges again next month; without `--write` it reports the differences and exits 2. It **refuses to approximate**: no exact vendor+model match changes nothing, because a wrong limit is enforced by code while a missing one is only reported as unchecked (same rule as `find_bundled`'s no-fuzzy-match, `project-intake.md §4`). Matching is on the vendor+model INSIDE the file, so the filename is cosmetic; the convention is `<vendor>-<model>.json`.
* **`rew_tool/project_seed.py`** — start a new project from an existing one's **system parameters** instead of from nothing. Ported from `autosound-tcc`'s `core/project_seed.py` (2026-08-23) with its classification intact; it moved here because `project-schema.md` and `project.py` live here — the code that WRITES `project.json` belongs where the schema is, or the two drift and the copy outside the schema drifts silently. Splits the file three ways: **the system** (`car`, `source`, `dsp`, `amps`, `mic`, `hardware`, `channels`, `glossary`, `channel_summary`, `presets`) travels; **the findings** (`acoustics.flaws`, `_open_questions`) are offered, **off by default, never silent** — their `evidence` names measurements that exist only in the source project; **the project's own** (`project_rev`, and all of `paths` except `measurements_repo`, which points at the car rather than the tune) stays behind. An **allowlist, not a blocklist** — `state/`, `journal/`, `.tcc/` and whatever the schema grows next are never reached rather than excluded by a rule somebody has to maintain. Written through `Project.save()`, so it is validated, atomic, and gets `project_rev` 1 instead of inheriting a count of writes it was not part of; the seeding appends itself to `sources`. Prose (`autosound_context.md`, `preference-profile.md`) is copied with a marker under its title so an inherited profile is not mistaken for one written here — `note=` takes a translated marker. `Seeded.profile_open` counts what `dsp_profile.open_questions()` still reports on the COPIED profile, so a caller can say "inherited, 2 facts still open" rather than let a `null` read as settled. `--no-profile` for the case where the new build has a different DSP. Refuses rather than merges into a directory that already has a `project.json`. `project_seed.py <source> <target> [--findings] [--no-profile] [--note TEXT] [--json]` · `--describe <dir>` for a picker's one-liner; `--selftest`. stdlib only.
* **`rew_api.get_timing(mid)`** — **the one exported reader of a measurement's TIME BASE**, for the skill and `autosound-tcc` alike. Returns `{reference, offset_s, has_ir, ir_start_s, ir_peak_s, sample_rate, start_freq, end_freq, notes_offset_s, notes_agrees, …}`. Exported rather than left as something each consumer digs out of a raw record, because two readings of REW's timing fields is how the two halves of a project come to disagree about when a sweep happened. The rules it encodes: **`offset_s` is authoritative** (the prose in `notes` is a cross-check and can be edited without touching the field); **`reference` alone is not evidence** of a shared time base — it says `"Loopback"` at any offset, so compare the PAIR; **`ir_start_s` is the anchor, not `ir_peak_s`** (the start is on the sample grid and bit-stable, the peak wanders); **an RTA has no IR**, so `has_ir` is False and that is not a disagreement. Read-only. Its contract is pinned in `rew_api`'s selftest because it crosses a repo boundary.
* **`rew_tool/eq_export.py`** — **a channel to and from the clipboard, BOTH directions.** `export_eq(profile, eq_rows, crossovers=…, fmt=…)` and `import_eq(text, profile=…, fmt=…)` are separate calls, because they answer different questions and fail differently: an export asks *what does this DSP take*, an import asks *what is this text* and must cope with a block pasted from anywhere. `sniff(text)` names a block from its first line; an unrecognised one is REFUSED, since guessing a layout reads numbers out of the wrong columns. `import_eq` returns ledger-shaped `eq` rows plus `crossovers`, and flags that applying them changes what the driver plays. **The format is a parameter** (`fmt`) so a GUI or an agent chooses; omitted, the profile's vendor decides. `FORMATS` lists what is available and `register_format()` adds one mid-session — a format we do not hold is one the tuner supplies, never one we invent. **`DEFAULT_FORMAT` is `generic`**; Extended is substituted only when there is a crossover to carry, and the swap is reported. Asking for plain `generic` WITH crossovers in hand drops them and names the flavour that would carry them, rather than silently upgrading. Everything below still holds — one channel to the clipboard, in whatever the target DSP takes.** `export_eq(profile, eq_rows, crossovers=…) -> Export(text, format_name, written, crossovers, bank_size, left_out, notes)`. Dispatch is on the profile's VENDOR, because a format belongs to the vendor: one Audiotec-Fischer writer serves Helix / MATCH / BRAX and the bank SIZE comes from `eq.bands_per_channel`, never a constant — the size is written into the header, so a hardcoded 30 emits a header that lies. **`format_name` travels with the text**: a clipboard nobody can identify is a trap. **Crossovers:** never on Audiotec-Fischer (that bank is EQ only and this vendor keeps crossovers as separate device fields — they are reported in `left_out`, not smuggled in); on REW Generic yes, and the FLAVOUR follows the content — `Extended` when there is a leg to carry, plain `Generic` when there is not. A tier whose profile says it has no crossover (`no_crossover`, or no `hp`/`lp` in its fields) gets none whatever the format, so a virtual channel is excluded by its own profile rather than by special-casing the word "virtual"; `fields: null` is *not enumerated* and does not count as saying so. Nothing is dropped silently — every omission carries a reason. CLI: `eq_export.py <project> <channel> [--preset] [--version] [--fmt] [--out FILE]` — the channel's bank from the ledger in the DSP's format, with what was LEFT OUT on stderr (exit 3 when the bank could not carry all of it).
* **`rew_tool/generic_eq.py`** — REW's **Generic** / **Extended** block (Manufacturer "Generic"), the default when a DSP has no format of its own. A real pasteable block, not a listing to type from. 20 slots, 14 columns, and **precision that is not the ATF bank's** — frequency to 2 dp against 1, a PK's Q to 3 against 2. Byte-checked against the author's own exports of both flavours. Crossovers: `Extended` carries them **inline as numbered rows** (`High_pass` / `Low_pass`, `BU` = Butterworth, `L-R` = Linkwitz-Riley, slope in dB/oct), plain `Generic` in a trailing `Compound_filters` section — that section is READ but not written, since two ways to write one fact is how they come to disagree.
* **`rew_tool/predict.py`** — **the full-state predictor** (`virtual-first`): solos on ONE time base × the ledger's chains → what the mic would hear. `--solos DIR` (Resonalyze v7 files; `resonalyze_ir.py` writes them from REW) or `--rew --ver N` (live REW, refused unless on the loopback base with zero offset); `--project DIR` (active slot HEAD, schema-v3 rows: gain · polarity · delay · hp/lp · eq incl. APF) or `--state-json FILE [--state-key K]` (the anchors shape stage 0 used); `--drift MANIFEST` re-times each solo by the set's measured control drift. **The protective filter comes OUT of every solo before the chain goes on** (doctrine, `project-intake.md §3`): a v7 file says what was in the chain (`rewSource.protectiveHighPass`); a REW solo is answered by the capture round's record (`--process DIR`, the same record `analyze-joints --process` reads; default `$AUTOSOUND_PROJECT_DIR/process`); `--baseline` refuses an unmarked REW channel instead of reading it as configured; `--no-de-embed` leaves the filters in, to see what the doctrine changes. A round is found by EITHER key it carries — the version `capture-start` was given or the `_N` of the titles it expected/took — and **when `--process` is given and no round matches, the run is refused** with the rounds on record listed (the same in `analyze-joints --process` and `resonalyze_ir --process`); a v7 file's `rewSource.protectiveState` (`raw` / `bare` / `unknown`, written since 3.0.28) says what a `null` high-pass means, and a file without it is read as unfiltered and SAID to predate the mark. Every channel gets a note saying which it was, and where the 40 dB correction cap starts. Output: every channel processed, sums L / R / ALL, every junction from the crossovers with **both rulers** — `sum_loss` avg / dip / score AND the worst null — plus the L−R level difference per band; `--out DIR` writes `predicted.json` (`--plot` adds `predicted.png`). Refuses `phase_deg` (a vendor angle — use `APF1`/`APF2` bands); leaves the virtual tier and centre/rear out and SAYS so. Reproduces `sound_AutoSci`'s stage-0 prediction to 3·10⁻¹⁴ dB on the real set-02. `--selftest`. numpy + scipy. **`--align`** (Phase 1.3 as a command): delay × polarity per junction by sum loss, bottom-up, on the DSP's grid, the search widened to the members' arrival difference and an ALIAS (a good score one cycle off) said by name with the physical candidate taken; `--out` writes `aligned-delta.json`, the shape `apply.propose` takes. **`--route VIRTUAL=out,out`**: the ledger's virtual tier enters the chain of the outputs it feeds — a routing fact the user reads off the DSP, never guessed.
* **`rew_tool/verify_prediction.py`** — **predicted vs measured, on the same terms** (the model-trust metric). `--predicted predicted.json` + `--rew --ver N` (titles `<lo>+<hi>_N (sw)`, `<ch>_N (sw)`, `ALL_N (sw)`; `--pair lo,hi=TITLE` / `--solo ch=TITLE` / `--all TITLE` to override) or `--measured DIR` of v7 files. Per junction the **interference term** (pair − power-sum of the solos) predicted vs measured in three log sub-bands; |mean Δ| ≤ 1 dB everywhere → `TRUSTED`, else `NOT trusted at …`. Channel shapes and ALL after one offset each (the offset is a calibration fact, reported). RTA rows refused unless `--allow-rta`, and then said in the verdict — a point prediction is verified by point sweeps from the tripod. Exit 0 only on `TRUSTED`. Not `verify.py` (the capture gate). `--selftest`. **`--entry`** (Phase 3.1, the entry control): each measured `_2` solo against the predicted solo × chain on 1/6-oct-smoothed shapes plus an ARRIVAL check from the complex response — a corner or a band typed wrong is CHECK with the nearest chain feature named; a delay typed wrong is caught by the arrival, which the shape cannot see. `--measured DIR` (v7) reads through `predict`'s own loader.
* **`rew_tool/protective.py`** — **what was in the signal chain while measuring, and taking it back out.** A driver swept behind a protective high-pass carries that filter's PHASE far past its corner, and nothing downstream can tell, because a protective `LR4 @100` and a designed one are the same filter. Measured here: an `LR4 @100` still leaves **52°** at 320 Hz, and — symmetrically — an `LR4 @500` leaves **53.5°** at 160 Hz, so **low-passes count exactly as much**; a tool de-embedding only high-passes would clean half the problem and look finished. On real data the same junction read **−49°** with protection in and **+3°** with it removed. `de_embed(freqs, measured, legs)` divides the chain back out and **reports the boost cap** (40 dB, as Resonalyze uses): below a protective corner the filter has almost no output, so dividing by it lifts the noise floor and would hand back hiss shaped like a driver — inside that region the phase is not recovered and says so. `matters_at(legs, f)` is the degrees still unwound, and the threshold is in **degrees, never in distance**: the residual falls as roughly 1/ratio and scales with slope, so eight times out is still 20° for an LR4 and 29° for an LR6 (a ratio rule was tried and the maths refuted it). **Working by default, raw by exception** (the user's rule): a capture nobody marked measured the system AS CONFIGURED, so its filters belong to the tune and are not removed — that is an answer, and it costs no clicks in the common case. `should_de_embed()` returns `no` / `yes` / **`check`**, the last being the one hole named rather than papered over: with "working" as the default a FORGOTTEN flag is silent and costs ~50°, and nothing in the data can reveal it, since a protective `LR4 @100` and a designed one are identical. A **baseline** sweep predates any crossover, so filters in force during one are protection almost by definition — pass `baseline=True` and an unmarked one comes back as a question for a person, not a guess. ⚠️ Do not de-embed when verifying a finished tune: there the filter belongs, and removing it measures something nobody configured. `--selftest`.
* **`rew_tool/timebase.py`** — **were these measurements captured the same way?** The batch comparability gate, for when a project accumulates captures across sessions (a second visit, a repaired door, somebody else's files). Compares **timing reference AND offset** as a pair, sample rate, and sweep range; reports, never repairs. **The trap it exists for: `timingReference` is not evidence of a shared time base** — it reads `"Loopback"` whether the offset is 0 or 7.7 ms, so two batches can both look right in every UI and be 4 ms (1.4 m) apart. Verified against a live REW on the 77–82 set: three offset groups found (0 / 4 / 7.7003 ms) all claiming `Loopback`. Reads `notes` **only to cross-check** the numeric field — the prose is user-editable and editing it does not change `timingOffset` (caught a real hand-edited measurement whose notes said 5 ms while the field said 4). Distinguishes three states a naive check conflates: **`comparable`** (terms match and were stated), **`agree`** (nothing contradicts, but nothing states the time base either — safe to compare WITHIN the batch, not against another day), and a **mismatch**. RTA measurements have no IR, so they are set aside rather than failed, while still being compared on rate and sweep. Unknowns roll up by what is missing, not per measurement. `timebase.py --all | --title SUBSTR | --id N [--json]`; exit `0` comparable / `1` not on one footing / `2` unverifiable; `--selftest`. Read-only against REW (it may be mid-session). stdlib only.
* **`rew_tool/listening.py`** — **the listening vocabulary, the track catalogue and the routes, read from their markdown homes** (2026-08-25). Three tables in two files joined by ids: `references/patterns/listening-cheat-sheet.md` holds the CHARACTERISTICS (`c01`…: label, name, sounds right, sounds wrong, where a ✗ goes) and the ROUTES (`first` · `short` · `full` · `league`, ordered track × characteristic pairs); `test-tracks.md` holds the TRACKS (id, library, number, artist, title, version) and the LINKS (track × characteristic with only what is specific to the track — a `mm:ss` timecode, a cue). `characteristics(lang)`, `tracks()`, `links(lang)`, `routes()`, `check(lang)`; CLI `listening.py [characteristics|tracks|links|routes|check] [--lang uk] [--json]`. Translations are sibling files with the SAME ids (`listening-cheat-sheet.<lang>.md`, `test-tracks.<lang>.md` for the cues); a missing translation falls back to the English text marked `translated: False` — never an empty menu entry. An unknown id, a moved column, a timecode that is not `mm:ss` are exceptions, not skipped rows; the selftest runs on the REAL files and fails the suite on an orphan in either direction (an id a link or route names that does not exist; a characteristic no track exposes; a track exposing nothing; a route pair with no link row), in English and in every translation on disk, and on any *sounds right / wrong* phrase repeated in a cue. Why a parser and not a JSON next to the markdown (autosound-tcc's ask): a copy drifts in silence; when the file's form moves, this selftest fails here, not a panel in a car. stdlib only. The verdicts a listener gives are written by `state/process.py listening-verdict` (one writer, ids validated against this module) and read back by `listening-verdicts` — see that CLI's help.
* **`rew_tool/resonalyze_vc.py`** — the return leg of `resonalyze_ir.py`: a [Resonalyze](https://github.com/DIMOSUS/Resonalyze) **Virtual DSP session** (`resonalyze-virtual-crossover` v7) → schema-v3 **ledger rows** (`{hp, lp, gain_db, ta_ms, polarity, eq, status: proposed}`), one per sourced leg, each with a machine-readable per-field verdict against the project's `dsp_profile.json`. Anybody's Virtual DSP tune becomes a proposal our ledger can read, through one function the terminal and a GUI both call. **Nothing is rounded to fit:** a leg the DSP cannot enter keeps the value asked for and is marked `enterable: false` (a session may ask for LR48 on an edge; a Helix has LR 12/24/36, and picking LR36 on the tuner's behalf would be a tuning decision wearing a conversion's clothes). **A limit the profile does not state is `unknown`, never `ok`** — every such verdict names the profile key that would settle it, and they roll up into `profile_gaps`. Four traps it exists to get right: `crossoverKind` decides which edge is live and the dormant edge still holds values (often the C# default LR 2000/24, and on a sub a 10 Hz high-pass the session does **not** apply); `stereoSceneOffsetMs`/`stereoLevelDifferenceDb` are the **aim** of Auto delay/gain balance and are already inside each leg's numbers, with the SIGN of both carrying the drive layout rather than a value; `IsTransparent` is derived, not a bypass; and v7 keeps `enabled`/`bypass` on the **pair** only (upstream `bcf6cc3`), so a side-first read would hand back a muted leg as playing. Q passes through unchanged — Resonalyze stores RBJ, which is what Audiotec-Fischer reads. Binds legs to channels through `project.resolve_channel` (code → id → `previous_names`), never guessing: an unmatched leg stays `UNBOUND`. Emits rows; **banking them is `state/apply.py`'s gated job**, not this module's. `resonalyze_vc.py <session.json> --project DIR [--profile F] [--group G] [--map NAME=CODE] [--json]`; exit `0` all clear / `1` not enterable / `2` unverifiable; `--selftest`. stdlib only.
* **`rew_tool/verify.py`** — **is this measurement there, and is it usable?** A verdict per REW title, as data: `{"name", "exists", "valid", "issues", "stats"}` (SCR-013). `exists: false` is "nobody measured it"; `valid: false` is "it was measured and cannot be used" — a different conversation and a different colour on a front-end's checklist. Checks the FR is not empty, not flat to under a dB (a loopback or a placeholder, not a driver in a car), not silence, and not truncated short of the band asked for. The impulse stats are **reported, never judged**: `pre_ringing_dB` is everything before the peak, which on a real car sweep includes the loopback reference. CLI: `python3 rew_tool/verify.py "<title>" [...] [--json] [--band LOW HIGH]`, exit 0 when every title is valid. Importable: `from verify import verify, verdict, summary`. **`--session`** (Phase 0.6, also `capture-check --session`): the whole session in one table — live-band level, IR peak, pre-ringing, arrival, capture rate per title; loudest/quietest; the **drift record** `<x>-ctl1 → <x>-ctl3` by cross-correlation to a few hundredths of a capture sample (held within half a sample / moved / missing), written onto the round.
* **`rew_tool/verify_measurements.py`**
  * A one-off session script (VW Passat), kept as it was: hardcoded measurement ids, a Ukrainian report, impulse peaks → initial time-alignment delays → acoustic crossover intersection frequencies. Read it for the method; call `verify.py` for an answer.
* **`rew_tool/make_plot.py`**
  * Visual RTA plotting utility that generates comparative charts (L/R measurements vs. house/target curves) for visual-acoustic analysis.
* **`rew_tool/ellipsoid.py`** — **what STAYS and what MOVES across the nine hand-held positions around the head** (Phase 0.3 → the EQ decision). Per 1/6-oct band the mean and **σ(f)** — the spread the target tolerance is built from (`max(1 dB, 2σ)`); the three centre returns as one position and a drift floor; every feature of the mean curve tracked for PRESENCE at its own frequency (same sign, ≥ half the depth, extremum within a quarter of its width, in ≥ 80 % of positions) → *STAYS* (the system; EQ may address it) or *MOVES* (the position; not a filter); the **Q ceiling per octave band** from the narrowest feature that stays, borrowed Q ≤ 6 and SAID where none does. `--solos DIR --channel m-L` (v7 `<code>-pN.json`) or `--rew --ver N` (titles `m-L p1_N (sw)`). Verify: `--selftest`.
* **`rew_tool/eq_propose.py`** — **EQ as PACKAGES through the gates, never a curve fit** (Phase 2.1 / 3.3). Computed in the doctrine's order on the curves the earlier packages leave: `res:<group>` — driver resonances per group (sub+midbass / mids / tweeters): a medium-width peak (1/6–2/3 oct against a one-octave trend) that stays in the ellipsoid, passes the excess-phase gate (built from the impulse — no REW needed), sits outside ±1 oct of a junction, above Schroeder a peak only; cut by its height with the trend's absorbed share put back, Q ≤ the ceiling; `lr:<pair>` — one shape for L and R, cut on the louder side, shelves / Q ≤ 1, until |L−R| ≤ 1 dB per 1/3 oct in 300–4000 Hz (the pair's level offset reported as a GAIN matter); `tone:<pair>` — the pair toward the target on the 1/3-oct scale, identically both sides, tolerance max(1 dB, 2σ). Cuts only unless `--allow-boost` and the gate. Each package: WHY, the listening id, a score before/after, its `apply.propose` delta (`--out` → `eq-<id>.json`; `--accept a,b` merges). `--project P --solos DIR|--rew --ver N --house curve.txt [--ellipsoid DIR] [--route VFL=w-L,m-L,tw-L]`.
* **`rew_tool/ear_suspects.py`** — **what "cuts the ear" and what "booms", named on the curve and settled by A/B** (Phase 3.3, and any taste pass). Peaks above a ±1-oct median trend (≥ 3 dB, ≥ 4 in the bass, 1/12–1 oct wide), classed by where they sit (booms 40–120, boxy 150–300, nasal 0.8–2k, cuts 2–5k, sibilant 5–9k), ear-weighted (ISO 226 at the listening level); the **top three**, one conservative correction each (half the prominence, the widest Q that covers it), the cheat-sheet characteristic and phrases, and the `listening-verdict` line that records the answer (`--text "suspect:<id>=better|same|worse"`); `--round K --process DIR` drops what was heard as same/worse, a fourth round is refused. A sweep adds how long a bass suspect rings. `--rew --title "ALL_2 (rta)"` or `--file curve.txt`.
* **`rew_tool/rew_stub.py`** — **the four REW endpoints the tools read, served from files** (`/measurements`, a record, `frequency-response`, `impulse-response`; read-only, 404 by name for the rest). `rew_api` honours **`REW_API_URL`**, so `capture-check --session`, `predict --rew`, `verify_prediction --rew` and `ear_suspects --rew` run against an archived v7 session with no REW: `rew_stub.py --from-v7 DIR --ver 49` serves `<code>_49 (sw)` titles. What `path_check` uses for the in-car branch.
* **`rew_tool/path_check.py`** — **the whole virtual-first path END TO END on synthetic drivers, in the suite** (`--selftest`): a temporary project, drivers with defined arrivals / one backwards wire / protectives / a planted resonance, walked through the real command lines — contract → capture round + marks + the drift record → de-embed and `--align` → `apply.propose` × 2, `eq_export`, `eq_propose` (one package cut, banked, predicted gone) → `--entry` with planted entry errors, the clean set, one pair moved → the same in-car commands through the REW stub → `ear_suspects` on an MMM with a verdict round → refusals by name → a listening verdict. Every module has a selftest; this one checks the SEAMS. Run it after any change to `predict` / `verify*` / `naming` / `process` / `apply` / `eq_*`.
* **`rew_tool/rew_tool.py`**
  * Main CLI entry point. Two modes:
    * **Interactive** (no args) — deep dive on **one** measurement at a time (FR + GD + IR + distortion + target).
    * **`analyze-batch "<pattern>"`** — **mass analysis** of every measurement whose title contains `<pattern>` (e.g. `analyze-batch "_2 (rta)"`) in **one** consolidated deviation matrix: per-driver band-mean deviation vs its per-band target, plus an `anchor` column (300–3000 Hz offset — subtract from the bands to read pure shape) and `ripple` (post-anchor spread). One `get_measurements` + one **FR-only** `get_fr` per driver (not the 5-endpoint interactive fan-out), so a whole batch is ~5× fewer round-trips and one review-ready table instead of N dumps. Use it for the **mass read** in Phase 1 §5 (all `_2` drivers vs targets) and **Phase 2a hygiene** (diagnose every channel in one pass) — then drill into a specific driver interactively if a cell looks off. `--no-targets` = band levels only.
    * **`analyze-joints --joint "lo,hi,fc[,pair]" …`** — **mass joint analysis** (Phase 2b): walks every adjacent joint in one pass and renders one table (polarity · drift-immune delay from `align_by_summation` · residual null · APF f0/Q), reusing `joint_analysis.py` unchanged. **Honest by construction** — a computed delay/polarity/APF is emitted **only** when a measured `pair` reproduces the complex solos (`phase_trust_gate` passes ✓); if the pair is missing → row flagged **UNVERIFIED** (confirm by summation before entering); if the gate trips → **BLOCK**, no delay emitted, fall back to the magnitude power-sum verdict + "flip polarity, re-measure". `--ver N` picks the solo version (`<ch>_N (sw)`, default 2), `--band-oct` sets the ±octave joint window. **`--from-state`** auto-derives the whole joint map (adjacent driver pairs + crossover freqs) from the **active slot's** crossovers in `state/` (no hand-typed `lo,hi,fc`) — works against the active registry slot by default (multi-slot guardrail), `--preset`/`--state-ver` to override; a manual `--joint` then supplements/refines (e.g. attaches a measured `pair` to one joint). Examples: `analyze-joints --from-state` · `analyze-joints --from-state --joint "sw,w-L,60,SW+Ws_2 (rta)"` · manual: `analyze-joints --joint "w-L,m-L,400" --joint "m-L,tw-L,3000"`. **`--apf "ch,APF1,f0"` / `--apf "ch,APF2,f0,Q"` — a candidate all-pass to VERIFY, not propose** (SCR-050): the one the Arbiter dialled by hand in TCC's curve window against the predicted sum. Every joint touching that channel gets one more line — the joint's worst null *as it stands*, *with the candidate and nothing else changed* (the reading TCC's sum showed), and *with the candidate plus the best further delay* — under the **same trust gate** as its row: no pair → the candidate is UNVERIFIED too; gate tripped → nothing is computed for it. One candidate per channel; the Helix phase ANGLE is not accepted (it is one vendor's control, `helix-phase-allpass.md`). **`--process <project>/process`** (default `$AUTOSOUND_PROJECT_DIR/process`) reads the capture round's protective record for `--ver` (`process.py protective_record_for`, replayed from the journal so a closed round counts): a solo marked raw is **de-embedded** (`protective.de_embed`, boost cap reported per channel) before its phase is read; an unmarked **baseline** solo (`_1`, or the round's phase 0/−1, or `--baseline`) is refused as **`check protective`** with the question for the Arbiter, no number; an unmarked later solo is a working capture and is left alone. Doctrine: `project-intake.md §3`.
    * `python3 rew_tool.py selftest` = offline check of both batch + joints paths (no live REW).
* **`rew_tool/provenance.py`** — **which checkout of the method wrote a file**, asked in one place (autosound-hub HUB-002). `skill_sha()` is `git rev-parse HEAD` in this checkout, whole, validated as forty hex characters so that `fatal: not a git repository` cannot stand in an identifier field; `""` when there is no repository or no git, which is an answer and not an error. The writers stamp it themselves — `state/process.py` as the journal's `written_by` header, `dsp_profile.save_profile` as a wrapper-level `skill_sha` — because a number handed down by a front-end says what the front-end believes, not which code wrote the file. **The sha is the identifier; `plugin.json`'s version is the signature a person quotes** (`main` carries 3.0.36 while `marketplace.json` says 2.8.3, measured 2026-08-27 — a hand-kept number drifts, a sha does not), and there is exactly one spelling of it: no short form is written anywhere, so an artifact brought back from a weekend can be compared with another instead of trusted. The same walk and the same markers as `autosound-tcc`'s `core/install_report.skill_sha`, so the number in the artifact and the number on its screen agree by construction. `python3 provenance.py` prints the stamp; `--selftest`. stdlib only.

## Working Guidelines

1. **Numerical Data over Screenshots:** Prefer pulling data numerically over reading screenshots.
2. **Analysis Protocol:**
   * To decide what REW measurement (FR, GD, IR, etc.) to pull for a given task, refer to [analysis-playbook.md](references/core/analysis-playbook.md).
   * For advice on interpreting data (anchor-to-mids, peak-vs-null, power-sum summation, joint-phase checks, etc.), refer to [diagnostic-techniques.md](references/core/diagnostic-techniques.md).
3. **API Quirks & Gotchas:**
   * Watch out for big-endian float32 encoding, the requirement to `set_filters` one-by-one with `gaindB`, addressing measurements strictly by NAME instead of index, IR timing usability details, and out-of-band target curve garbage.
   * Check [rew-api-quirks.md](references/tooling/rew-api-quirks.md) for full documentation. (The `rew_tool/` codebase already handles these quirks).
4. **Fallback:** If the API cannot be reached from the host, fall back to the user's exported `.mdat` / CSV (e.g., `rew_analitic/measurements-*.mdat`) or screenshots.
